# W8 实现记录（M-6 依赖清单 + `platform-probe`）

> 对应 `docs/dependency-manifest.md`（20 条依赖点）。状态：**已实现** · 普通 Node `PASS 13 / FAIL 0 / N-A 13` · Electron `PASS 25 / FAIL 0 / N-A 0 / INFO 2`。

## 一句话

把「本插件建立在若干非公开 API 与行号事实之上」这件事，从**文档**变成**可执行断言**：
DSH 一升级，`npm run probe` 跑一次就知道哪几条破了，而不是等面板空白或闸门失灵才发现。

## 两种运行方式，以及为什么必须有两种

```bash
npm run probe            # 普通 Node：patch 边界、装载形态、自身契约、清单完整性
ELECTRON_RUN_AS_NODE=1 "/Applications/DeepSeek Harness.app/Contents/MacOS/DeepSeek Harness" \
  scripts/platform-probe.mjs    # 进 asar：宿主源码面 + 宿主包存在性
```

`picomatch` 与 `@deepseek-ai/*` 的源码都在 `app.asar` **归档内部**，只有 App 自带 Electron 的 Node fs 能读。
普通 Node 下这些项一律标 `N-A`，**绝不猜成 PASS**。

> 这条不是洁癖，是 W0 追加五那个教训的直接产物：当初用 bash 工具环境去判断「宿主里 picomatch 能否解析」，
> 得出的是反向结论。探针如果也这么干，就会把「检不了」说成「坏了」，或者更糟——把「没验证」说成「好的」。

## 四个状态，各有各的处置

| 状态 | 含义 | 处置 |
|---|---|---|
| `PASS` | 假设成立 | 无 |
| `FAIL` | 假设已破 | 按清单「兜底方案」降级；退出码非 0 |
| `N-A` | 当前环境检不了 | 换运行时再跑（普通 Node ↔ Electron） |
| `INFO` | 成立但值得知道 | 例：D9 worktree 已装（二期可提前试）；D12 上游若补 fsync 可删自实现约 40 行 |

## 探针自己写错的三条（值得留档）

第一版 Electron 下报 `D6/D8/D15` 三个 FAIL。核查后**全是探针的断言写错了**，不是依赖破了：

| 项 | 我最初猜的断言 | 实际 |
|---|---|---|
| D6 | `dsh-tools/lib/index.js` 里有 `"deny"` | 决策契约在 `src/contracts.ts` 的 `PreToolDecision`，编译产物在 `lib/types/pipeline.js` |
| D8 | 同上找 `"block"` | `PostToolDecision` 在 `src/contracts.ts` |
| D15 | 同上找 `"Input rewriting is excluded"` | 同一文件里的注释 |

修法：改成**多文件回退**（`src/contracts.ts` → `lib/types/pipeline.js`），任一命中即 PASS；
都命中不到仍然 FAIL —— 「文件在」不等于「假设成立」。

另一条：D19 第一版在普通 Node 下判 FAIL（`backend=fallback`）。这是**必然**的（picomatch 在 asar 内），
所以普通 Node 下必须标 `N-A`。判成 FAIL 的后果是每次本地跑探针都红，红久了就没人看它了。

> 结论：探针的断言也是代码，也会写错。**FAIL 要能被解释**，不能红着就算数。

## 探针覆盖什么、不覆盖什么

覆盖（可机检的假设）：patch 里的岗位工具边界、装载形态、profile bundles、`engines.dsh`、
宿主的 `PreToolDecision.deny` / `PostToolDecision.block` / 参数不可改写 / 沙箱 workspaceRoot 宿主级、
atomic-write 仍不提供 fsync、宿主包存在性、本插件自身三条关键契约（双门槛默认值 / intent schema / 审批文件位置）、
清单 D1–D20 无缺项。

**不覆盖**：运行时行为（如 W0 ⑤⑥ 的档位实际生效、面板 `retain` 是否真收到事件流）。
客户端 D1–D3 只做**静态源码断言**，报告里明确写了「弱」。这些只能靠真机会话验。

## 没接进门禁，是有意的

`platform-probe` **没有**加进 `prepublishOnly`。理由：它的语义是「DSH 升级后跑一次」，
而不是「每次提交都要绿」；且完整覆盖需要 Electron 运行时，发布机未必有。
它属于清单 §二 的升级自查第一步，不是日常五道门里的第六道。
