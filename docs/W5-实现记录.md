## 执行位置的分工（§14.6 补 3 修正）

| 位置 | 用例 | 为什么 |
|---|---|---|
| **scratch 工作区**（每个用例一个一次性 git 仓库，跑完即删） | 1–7 | 逻辑全靠插件自身代码，scratch 足以覆盖，且零污染 |
| **一次性克隆的真实项目**（`git clone --depth 1` 本仓库到临时目录） | 8–9 | 要真实结构：真实沙箱、真实文件树、真实忽略规则 |

Marvis 原话说「8/9 必须真实仓库，因为 glob 依赖真实文件树」——**这一点不完全对**：
glob 匹配是 `(glob, 变更路径)` 的纯函数，scratch 里造同样的树也能测。
真正需要真实结构的是**端到端保真**，所以给了 8–9 一次性克隆，而不是「真实仓库 + `sampleTag`」。

## 样本隔离

`sampleTag` 挂在**卡**上，不挂在证据上（§14.6）：

- 理由：聚合只能经 `card join`，这样**一张卡内部不可能混样**；挂证据上就做不到。
- `null` 视为真实样本；本轮注入用例一律 `sampleTag: 'injected'`。
- `office_dispatch` 新增可选参数 `sampleTag: real | injected`，走标准 JSON Schema（不是属性级 `required`）。
- 报告里写明：**闸门通过率 / 回退率统计只取 `real`**，本报告不参与聚合（聚合本身在 M-12 实现）。

## 一个必须如实说明的缺口：第 3 例的「P1 来源校验」并未按 preset 校验

方案 §7.1c 把 P1 描述成「回执由宿主从子代理会话事件抓取 + **校验来源 preset**」。
实测与代码核查的结论：

| 项 | 现状 |
|---|---|
| 伪造文本能不能变成结论 | **不能** —— 结论只来自 `git-plumbing`，`cto-narrative` 被排除。这是最硬的防线，已实测 |
| 回执采集器是否校验「回执来自哪个 preset」 | **没有** —— `lib/receipt-collector.js` 只按卡号记账，不看 presets |

**影响评估（不是危言耸听，也不是洗白）**：回执只参与「声明 vs git 事实」的对齐，**不产出 verdict**，
所以一份来自错误 preset 的回执拿不到 PASS。风险有限，但「来源 preset 校验」确实是 P1 的未实现部分。
本轮**没有**顺手加：会话事件里虽然有 `agent-preset/selected`，但事件到卡号的映射要按子代理会话身份 join，
属于独立的接线工作，硬塞进 M-8 只会做出一个半成品。已在交接文档记为待办。

## 测具自己踩的坑（值得记）

第 7 例第一次跑 **FAIL**，但**不是实现缺陷**：模拟崩溃时我把卡里的 `artifactsVersion`（过滤掉 0 的**冻结子集**）
当成了 intent 登记值，而 gate 签名时用的是**全量 versions** → 每次都判 `stale-context`，于是新开事务。

- 修的是**测具**（改用 `artifacts.versions()`），不是被测代码。
- 顺手在 `office_gate` 里加了注释：`versions` 必须全量、与 `beginIntent` 同一口径，两处不可混用。

> 这类失败要分清：**测具写错**和**实现缺陷**看起来都是「红灯」，但改的方向完全相反。
