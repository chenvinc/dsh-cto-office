# P1 来源校验（补 M-8 暴露的缺口）

> 对应方案 §7.1c 里 P1 的「校验来源 preset」那半句。状态：**已实现** · 单测 **76/76**（新增 9 例）· E2E **28/28** · 注入 **9/9** 全绿。

## 缺口的原文记录（M-8 发现时）

方案把 P1 描述成「回执由宿主从子代理会话事件抓取 + **校验来源 preset**」。
实测与代码核查的结论是：

| 项 | 当时的状态 |
|---|---|
| 伪造文本能否变成结论 | 不能 —— 结论只来自 `git-plumbing`，自述被排除（这条已实测） |
| 采集器是否校验「回执来自哪个 preset」 | **没有** —— 只按卡号记账 |

影响有限（回执不产出 verdict），但这意味着**只读岗可以替写卡交一份「我改了这些文件」的回执**，
把「谁写的、谁自证」这条边界弄模糊。所以补上。

## 怎么补的：采集层记事实，判定层做判断

```
采集层  receipt-collector：用 agentPresets.presetForSession(session) 取 preset id
        → 写进回执：fromPreset / presetVerified
判定层  crossCheckReceipt：写卡若收到非写岗回执 → 违规 kind=receipt-source
```

三个刻意的取舍：

1. **宿主的返回是字符串，不是对象**。`agentPresetProjectionDefinition` 的 schema 是
   `z.union([string, null])`，所以 `presetForSession(session)` 直接给 preset id。
2. **拿不到 preset 时不 fail-closed 丢回执**。丢掉的后果是正常派工永远凑不齐、
   `receipt-missing` 天天报 —— 那是把「接口不可用」变成「办公室停摆」。
   所以采集层只记 `presetVerified: false`，**判定层不在未知来源上打回**。
   判断留在该做判断的地方，采集层不越权。
3. **写岗清单是参数**（`writerPresets`），不是写死的 `cto-builder`；
   测试里验证了「把 `cto-qa` 也列进写岗后，同一份回执不再违规」。

## 效果

| 场景 | 之前 | 现在 |
|---|---|---|
| `cto-builder` 交回执 | 记账 | 记账，**无违规** |
| `cto-architect` 替写卡交回执 | 记账，且可用于回执对齐 | 记账 + `presetVerified: true`；gate 判 **CHANGES（receipt-source）** |
| 宿主没暴露 `agentPresets` / 调用抛错 | 记账 | 记账，`presetVerified: false`，**不据此打回** |

回执的证据文件里也带 `fromPreset`，事后能归因「这份回执是谁交的」。

## 尚未覆盖的边界（如实写清）

- **只认「会话 → preset」这一层**。若有人在一个 `cto-builder` 会话里让模型自己去读别人的改动并交回执，
  这层看不出来 —— 那需要「回执与子代理会话归属」的更深绑定，属于二期。
- `agentPresets` 是**探测式使用**（cordis 对未 inject 的服务属性裸读会抛）。
  拿不到时降级为「只看格式与版本」，与一期 A 的行为一致。
- 这条不改变「结论只来自 git」这个最硬的防线；它只补「回执归属」的边界。
