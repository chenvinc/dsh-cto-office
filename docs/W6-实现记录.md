# W6 实现记录（M-12 指标 + 双门槛 + sampleTag 隔离）

> 对应方案 §14.7。状态：**已实现** · 单测 **67/67**（新增 12 例）· E2E **28/28** · 注入 **9/9** · 演练通过 · `check` 通过。

## 一句话

五类指标从已有机制算出来，再套一条**双门槛**：样本不够就**不给建议**（返回 `recommendation: null`），
够了也只看**趋势**（连续 2 个周期超阈值），不看单点。

## 五类指标与口径

| 指标 | 定义 | 分母 |
|---|---|---|
| 卡时长 | `createdAt → 终止态` 的毫秒数，给 p50 / p90 | 已终止的真实卡 |
| 阻塞率 | 曾进过 `QUEUED`（`blockedBy` 或 `queued`/`still-queued` 历史）的卡占比 | 真实卡 |
| 越界检出率 | 判定证据里出现 `out-of-scope` / `read-only-write` 的卡占比 | 真实卡 |
| 回退率 | `rounds >= 2`（回退与重试合并计数）的卡占比 | **有判定结论**的真实卡 |
| 共享文件冲突 | 两张卡的改动路径有交集 → 记一对冲突，列出共享路径 | 真实卡两两比较 |

全部从已有数据算：`card.json` + `evidence/*.json`，**不新增组件、不新增埋点**。
风险口径沿用 M-1：只认权威来源的判定证据，自述不进任何比率。

## 双门槛（补 4）

```
要给出建议，必须同时满足：
  ① 独立周期数 ≥ minCycles（默认 3）
  ② 真实卡数   ≥ minCards （默认 15）
  ③ 该指标连续 consecutiveBreaches（默认 2）个周期都超阈值
```

**第 ③ 条与「样本不足不给建议」是同一个道理**：单点抖动不是趋势。7 张卡上得出的
「应该建 worktree」，事后无法与「有数据支持」区分。

真实工作区（4 张卡、1 个周期）现在的输出，就是这个设计的样子：

```
样本：真实 4 张（注入 0 张已排除）
阻塞率 0%｜回退率 0%｜越界率 25%｜共享冲突 0 对
周期 1 个｜时长 p50 4 分钟
判据：数据不足（不给建议）
数据不足（卡数 4 < 15；周期数 1 < 3）。样本不足时不给建议 —— 凭判断拍板请用 action=early-decision 另记一笔。
```

## 阈值全是参数

```yaml
metrics:
  cycleDays: 7            # 周期长度
  minCycles: 3            # 独立周期门槛
  minCards: 15            # 样本卡数门槛
  consecutiveBreaches: 2  # 连续几个周期才算趋势
  thresholds:
    blockRate: 0.4
    reworkRate: 0.3
    outOfScopeRate: 0.2
```

`resolveMetricsConfig()` 统一合并默认值；测试里专门验证了「把 `blockRate` 门槛调到 1.01，
同一批样本立刻不再建议」—— 阈值写死在代码里的话这条测试会红。

## 周期怎么切（一个真踩过的坑）

周期 = 「自 **1970-01-05（周一）** 起的第几个 N 天」，**不是**「距今几天」。
后者会随运行时刻漂移，同一个样本今天算 3 个周期、明天算 2 个。

测试第一版手写了一个「2026-10-05 是周一」的起点，结果 `monday` 与 `monday + 6 天`
落到不同周期 —— 2026-10-05 根本不是周一。修法是让测试也按同一个 epoch 推算，
而不是手写日期。

## 样本隔离（§14.6–14.7）

- 过滤点在 `computeMetrics`：`card.sampleTag !== 'injected'` 才进分母。
- 标签挂在**卡**上，经 card join 过滤，所以一张卡内部不可能混样。
- `sample.real` / `sample.excludedInjected` 两个数都公开，报告里写明「注入样本不参与聚合」。
- 实测：2 真 + 2 注入的样本，若不隔离阻塞率会被从 50% 稀释成 75% —— 测试钉住了这个差异。

## 人工提前决策

允许人凭判断拍板，但记成**判断**而不是证据，且必须写 `reason`：

```json
{ "schema": "cto-office/early-decision@1", "decision": "early",
  "sampleState": "insufficient", "decidedBy": "human",
  "reason": "先并行验证", "cardCount": 3, "at": 1764...}
```

落盘：`.cto-office/metrics/early-decisions.jsonl`（一行一条，只追加）。
缺 `reason` 直接抛错 —— 审计里必须能分清「有数据支持」和「凭判断拍板」。

## 工具

`office_metrics(workspace, action: report | early-decision, reason?)`

- `report`（默认）：返回 `cardCount / blockRate / reworkRate / outOfScopeRate / conflicts / cycles / adviceState` 与人话摘要。
- `early-decision`：写一条判断记录，返回记录本体。
- 卡读不出来时在消息里点名，并把这些卡排除在指标之外（不让坏卡把统计做假）。
