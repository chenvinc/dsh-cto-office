# W3 实现记录（M-2 判定事务 · intentId + latest-wins + 持久化）

> 对应方案 §14.2（判定事务）/ §14.3（证据持久化）。
> 状态：**已实现** · 单测 **46/46**（新增 11 例）· E2E **28/28** · 演练通过 · `npm run check` 通过。

## 一句话

判定从「事后写一条证据」变成**事务**：先登记 `intent` → 再判定 → 落 `result`（只新建）→ 卡上记账 → 收尾。
崩溃点因此只剩「intent 有、result 无」，而那是**安全状态**。

## 为什么幂等键必须是 `intentId`

上一版想用内容三元组 `(cardId, baseSha, artifactsVersion)` 当幂等键。这是个会锁死卡的设计：

```
判定 → CHANGES → 改码 → 再判
```

修复后重跑时，`cardId`、`baseSha`、`artifactsVersion` **三者全都不变** —— 用它们当键会把重跑判成同一次动作，
卡被**永久钉在 CHANGES**。幂等键只能是「一次判定动作」本身，即每次新建的 UUID。

内容三元组退一步只做**有效性断言**：判定时若与 intent 登记的不一致 → 该 intent 作废（`stale-context`）、开新事务，
**不复用**。这挡的是「卡重开/重取 baseSha 后，旧 intent 被错误复用」。

## 三条不变量与落点

| 不变量 | 落点 | 守护测试 |
|---|---|---|
| intent **先于**判定落盘 | `office_gate` 里 `recoverIntents` → `beginIntent` 在 `collectFacts` 之前 | 「崩溃点是 intent 有、result 无」 |
| result **只新建、永不覆盖** | `writeOnceJson`，`EEXIST` 视为幂等命中 | 「同一 intentId 重写保留第一次结论」 |
| **latest-wins** | `recoverIntents`：只有 `intentSeq == max` 才可恢复；更旧的标 `abandoned` 且**不重跑** | 「只重跑最新 seq，旧孤儿落盘作废」 |

latest-wins 的理由：启动扫描若把**所有**孤儿都重跑，旧事务会用「当时的事实」产出一份**陈旧结论**，
而它可能时间更新、覆盖掉新结论。宁可留一条 `abandoned` 记录，也不产出陈旧判定。

## 目录布局

```
.cto-office/cards/<id>/intents/<seq:06>-<intentId>.json   ← 事务游标（pending → result-written / abandoned）
.cto-office/cards/<id>/evidence/<intentId>.json           ← 判定结论（只新建，永不覆盖）
```

`intents/` 与 `evidence/` 分开是有意的：前者是**可变游标**（覆盖替换五步），后者是**只读结论**（只新建）。
两者混在一起，就无法保证「结论永不被改写」。

`seq` 由**目录里现有的最大 seq + 1** 推出，不依赖 `card.json` 里的计数器 —— 目录才是崩溃后仍然权威的事实。

## 顺带修掉的一个真缺陷（不是重构，是行为变更）

原先结算读 `store.latestEvidence()` = 「最新的权威证据」。但**合规回执本身也是权威证据**（`subagent-session`），
只是没有 `verdict`。于是：

```
gate → PASS → 结算前回执又到一条 → latestEvidence 返回回执（无 verdict）
→ 结算报「最近一次闸门结论是 undefined」→ 正常工作流被拒
```

e2e 没暴露它，因为那里的顺序恰好是「回执先、判定后」。真实工作流里回执晚到很常见。

修法：新增 `store.latestJudgement()` —— 只认**有 `verdict` 的权威证据**，按 `intentSeq` 定序（无序号的老证据回落时间戳）。
`office_release action=settle` 改读它。`latestEvidence` 保留原语义供面板/统计使用。
测试里专门断言了「`latestEvidence` 会拿到回执、`latestJudgement` 不会」，把这个差异钉住。

## 读侧严格化（§14.3）

- `scanEvidence()` 把坏文件收进 `corrupt`，**不静默跳过**；`latestJudgement` 遇到 `corrupt` 直接抛 `CORRUPT`（fail-closed）。
- `office_gate` 遇到坏 intent 或坏证据 → 拒绝判定并点名文件，落结论数为 0。
- `listEvidence()` 保留宽容语义（面板不能因一张坏文件炸掉 `office_status`），但**判定路径不许用**，注释已写明。

## 与旧行为的差异（升级注意）

1. `office_gate` 的消息里多了 `intent #N`；崩溃恢复时显示「崩溃恢复 / 复用已落结论」。
2. 判定证据多两个字段：`intentId`、`intentSeq`。
3. 新增目录 `intents/`。
4. **老卡向后兼容**：没有 `intents/` 的卡第一次判定时从 seq 1 开始；老证据没有 `intentSeq`，
   `latestJudgement` 回落按 `at` 时间戳排序，不影响已结算/已作废的卡。

## 有意没做的三件（边界写清）

| 项 | 状态 | 理由 |
|---|---|---|
| §14.3「`CORRUPT` → 自动标 `abandoned`」 | **只拒绝判定 + 提示人工**，不自动作废 | 自动作废会掩盖问题；且 `abandoned` 是复合动作（释放 exclusive、重评 QUEUED），在「证据都读不出来」的状态下自动执行它，风险大于收益 |
| 启动时全量扫描 | **改为惰性**：每次 `office_gate` 先扫该卡 | 宿主 apply 时**还没有工作区**（`resolveWorkspace` 拒绝猜测），此时无法扫描；强行猜 workspace 会把 `.cto-office` 建到 app 目录 |
| 复合动作（`finalize`）也走同协议 | **未做**，仍是一步到位 | §14.4 要求「复合动作本身也可重启」。它需要单一 `releaseHold` 已存在（有），但事务化要另开一段；留到 M-8 故障注入时一起打靶 |
