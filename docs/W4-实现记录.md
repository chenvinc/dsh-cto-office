# W4 实现记录（证据来源分级 · P1 完全体）

> 对应方案 §14.1 / §14.2。
> 状态：**已实现，单测 23/23、E2E 24/24、演练通过**。

## 做了一件什么事

把「可靠性」从**论证**变成**数据属性**：

| `source` | 参与判定 | 说明 |
|---|---|---|
| `host-event` | ✅ | 宿主事件（工具结果、会话事件、post-execute 抓取） |
| `git-plumbing` | ✅ | git 原生命令输出 |
| `subagent-session` | ✅ | 子代理会话消息（RECEIPT 块） |
| `cto-narrative` | ❌ | CTO 自述：可记录、可给人看，**永不参与机器判定** |
| 未知来源 | ❌ | fail-closed：不认识就不信 |

## 三处落点

1. **`store.latestEvidence()` 只返回权威来源** —— 自述即使时间更新，也不会成为「最新结论」。
   结算（`office_release action=settle`）走的就是这条路径，所以**自述 PASS 解锁不了结算**。
2. **`office_note` 工具**显式记录自述，返回 `authoritative: false`，并在回执里说明「自述不参与判定」。
   它让「自述 vs 证据」的区分从文档变成可调用、可测试的东西。
3. **`office_status` 暴露来源统计**：每张卡的 `evidence.bySource` 与 `excluded`（被排除条数）。
   面板将来直接读这个，就能显示「这张卡有 1 条自述被排除」。

## 为什么必须做这一步

P1 只挡住了「往文件里写一行 `GATE:`」这一种伪造。但一期至少有四类证据
（越界结论、测试是否真跑、成本数字、工件版本），每加一类都靠人再论证一次
「这个能不能信」，迟早会漏。

来源写进枚举 + 白名单，只需论证一次；之后所有新证据只要声明 `source`，
判定层就自动知道该不该信。
