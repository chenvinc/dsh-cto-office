### 发现 1 · 输出 schema 必须是标准 JSON Schema 方言

首次安装报错（宿主 diagnostic 原文）：

```
cto-office-live (@swiper1881/dsh-cto-office): JsonSchemaError: unsupported JSON schema:
  schema.properties.cardId.required is not supported on type "string";
  schema.properties.blockedBy.required must be an array of strings; ...
```

**原因**：`parameters` 用的是 DSH 简化方言（属性上写 `required: true`），
但 `output.schema` 走**标准 JSON Schema** —— `required` 必须是对象层的字符串数组。

**修复**：`jsonSchemaOf(properties, required)` 统一把 `required` 提到对象层；
并加单测断言「属性上不得出现 `required`」，防止再犯。

### 发现 2 · 未声明 inject 就读服务属性会抛错

第二次报错：

```
cto-office-live (@swiper1881/dsh-cto-office): Error: cannot get property "timer" without inject
```

**原因**：`inject = ['tools']`，但代码里读了 `ctx.timer`。cordis 对未 inject 的服务属性
访问直接抛错（不是返回 undefined）。

**修复**：`try { timer = ctx.timer } catch { timer = undefined }`；
并加「严格 ctx」回归测试（Proxy 模拟 cordis 抛错）覆盖 `timer / agentPresets /
workingDirectory / sandboxPolicy` 四个可能的裸读点。

> 这两条都**只有装进真宿主才会暴露**：Node 单测里我用的是 fake ctx 与自造 schema，
> 假对象不会拒绝任何东西。这就是 W0 的价值。

## 三、另外两条真机行为（重要，影响以后的迭代方式）

1. **安装形态从「副本」变成 `link:`**：`list_bundles` 里 source 显示
   `link:/Users/chy/个人工作台/cto-office`。含义：
   - 改 `index.js` / `lib/` 后，`set_bundle false → true` 即生效（不必卸载重装）；
   - 但**改 `cordis.patch.yml` 需要重载**才重读（patch 不热更新）。
2. **卸载会同时移除 profile 里的依赖声明**：`remove_bundle` 后 `package.json` 里
   也没有了，重装才能恢复。这是「先卸再装」升级路径的真实代价，已在 README 记录。
