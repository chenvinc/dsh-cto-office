## 五、七个真机踩过的坑（**再犯一次就是浪费时间**）

1. **`parameters` 与 `output.schema` 都是标准 JSON Schema**：`required` 必须在对象层写数组，
   写成属性级 `required: true` 会被宿主拒（output）或静默放行（parameters，导致数组被字符串化）。
2. **cordis 未 inject 的服务属性裸读会抛**（`timer` / `agentPresets` / `workingDirectory`），
   且 `inject` **没有可选语义** → 只能 try/catch + 明确降级，绝不能靠它做安全判断。
3. **不要把工具注册在全局 host 半**。最初用 `when` 收窄，拿不到 `agentPresets` 就 fail-open，
   结果是 standard 会话和 worker 都能调 `office_*`。现在挂在预设作用域，无 fail-open 路径。
4. **工作区绝不猜测**：宿主进程 cwd 是 DSH 安装目录。工具必须显式传 `workspace`。
5. **git 必须关 `core.quotePath` 并用 `-z`**：否则中文路径被转义成 `"docs/W0-\345…"`，
   授权匹配与回执核对双向错位（已发生过，闸门自己抓到的）。
6. **`subagent` 立即返回的是「受理回执」**，worker 的最终答案走完成通知、不经过 `post-execute`。
   所以回执只能从 `session/event` 捡，**无法在通知上打回**；缺回执由 `gate` 的 `receipt-missing` 兜底。
7. **不许 `import '@deepseek-ai/*'`**：从插件目录解析会落到 npx 缓存的旧 rc（宿主是 rc.5）。
   能力一律走 `ctx`；工具定义用手写字面量。`dsh-atomic-write` 存在但**自己声明不做 fsync**，
   所以持久化自实现（`lib/atomic.js`），依赖清单 D12 记录了理由。

## 六、关键设计不变量（改代码前先读）

- **工件先于卡**：没有 `acceptance` 工件不许 `office_dispatch`。
- **`baseSha` 在「拿到写者名额那一刻」冻结**，不是建卡时（否则排队期间 main 前进会污染 diff）。
- **派工守卫按【任务卡 X】判定**：命中的是持锁卡 → 放行；是 QUEUED → 提示先启动；缺标记 → 拒。
- **省略 `agent_preset` 按写工处理**（宿主默认就是 `cto-builder`），否则一个参数绕过两道守卫。
- **结算必须**：工作区干净 + 最新**权威**证据为 `PASS`（自述写 PASS 不管用）。
- **终止态是复合动作**：归档 → 释放 `exclusive` → 重新评估 QUEUED 卡。
- **阈值是参数不是常量**（`rounds` 2/3、TTL、轮询间隔、粒度上限）。
