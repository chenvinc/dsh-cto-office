## 交付

| 文件 | 作用 |
|---|---|
| `lib/artifacts.js` | 工件层：契约/验收基线、版本号、`artifactsVersion`、进行期禁改 |
| `lib/receipt.js` | 回执协议：解析 `RECEIPT`/`SELF-CHECK`，校验字段、版本、范围、验收条目 |
| `lib/receipt-guard.js` | 挂在 `tools/post-execute`：写岗缺回执 → **block**，要求补齐重交 |
| `lib/tools.js`（扩展） | 新增 `office_artifact`；`office_dispatch` 冻结工件版本、无验收基线不许派工；`office_gate` 判定前先验工件 |

## 五条落地的约束

1. **工件先于卡**：没有 `acceptance` 工件，`office_dispatch` 直接拒绝 —— 没有对照物，闸门无从判起。
2. **版本冻结**：派工时把 `{contracts, acceptance}` 版本写进卡；只冻结**存在**的工件（`contracts` 可选）。
3. **进行期禁改**（M-14）：卡存在且非终止态（含 `QUEUED`）时，`office_artifact.write` 抛 `CARD_IN_PROGRESS`，要求作废重开。
4. **回执必须写读了哪一版**：`artifactsVersion` 与卡不一致 → 打回并说明「你读的是 v1，卡已定稿 v2」—— 返工责任可归因。
5. **缺字段 fail-closed**：回执是判定输入，缺就 block；与「判定器自身失败只告警」不冲突。

## 实现中发现并修正的 2 个语义问题

| # | 问题 | 修正 |
|---|---|---|
| 1 | 工件锁只覆盖 `DISPATCHED`/`CHANGES` | **`QUEUED` 也必须锁**：版本在开卡时就冻结了，排队期改口径同样造成「按 v1 做、按 v2 验」 |
| 2 | `contracts` 被当成必填 | 改为**可选**：小卡没有契约是合理的，但对齐时仍校验版本；`acceptance` 必填 |

## 增补：回执 × git 交叉核对（W2 收口）

### 做了什么

`office_gate` 不再只看 git，也不让回执自己判「越界」—— 两者**对齐**才放行：

| 违规 kind | 含义 |
|---|---|
| `receipt-missing` | 写卡没有回执记录（`acceptance` 等字段无从核对） |
| `receipt-overclaim` | 回执声称改了某文件，git 里没有它的改动 |
| `receipt-underclaim` | git 显示某文件被改，回执没声明 |

合规回执在 `post-execute` 通过后立刻 `store.recordReceipt()` 记账，并落一份
`source: 'subagent-session'` 证据 —— 这是 §14.1 四枚举里第二个真正用起来的来源。

### 发现并修正的一个设计问题

**原设计中，回执校验收 `changed` 必须 ⊆ 授权清单。这惩罚了诚实**：
老实的 worker 声明「我越界改了 shared/types.ts」会被回执闸门直接打回，
而把越界隐瞒掉反而能过闸 —— 结果是漏报变常态。

**修正**：回执校验收窄为「格式 / 完整性 / 版本」，**范围结论只由 `office_gate`
用 git 事实给**（单一事实来源）。回执里的越界路径改为记录 `parsed.outOfScope`
供 gate 使用，不判失败。

### 演练发现的两个数据问题（非代码问题）

1. 卡冻结了 `contracts=1`，回执只报 `acceptance=1` → 被正确拦下（设计如此：冻结了什么就要申报什么）。
2. 监督器报警没触发，是演练脚本把时间戳设错了卡（持有者 C1 而不是等待者 C2）。

### 新增可复跑命令

```bash
npm run rehearse   # 演练 + 磁盘核对：工件/卡/证据/报警实际留下什么，逐项列出来
```

`prepublishOnly` 现为：`check && test && e2e && rehearse`。
