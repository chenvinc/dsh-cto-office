> 对应方案 §14.9。状态：**已实现** · 单测 **55/55**（新增 9 例）· E2E **28/28** · 演练通过 · `npm run check` 通过。

## 三处门槛与它们的实现方式

| # | 漏洞 | 实现方式 | 为什么这样做 |
|---|---|---|---|
| 1 | 改 patch / preset 造空壳 reviewer 冒充来源 | **人工审批文件 + 能力边界** | 守卫看不到「人有没有点过确认」，所以真正的边界是审批文件的**位置** |
| 2 | 卡进行期改 `artifactsVersion` | `ArtifactStore.write` 对在飞卡直接 deny（一期 A 已实现，本轮补交叉测试） | 授权是判定的对照物，中途改就等于「按旧版做、按新版验」 |
| 3 | `exclusive` 释放靠自觉 | **锁 TTL + 活动续租 + 审计** | 不看意愿：久无动静的占用自动不再阻塞别人 |

## 第一处：改判定器本身需人工确认

**为什么 P1 挡不住**：P1 认为「证据来自子代理会话事件」就可信。但 CTO 可以改 `cordis.patch.yml`
造一个空壳 `cto-reviewer` preset —— 那时来源校验照样通过，因为来源**确实是一个 preset**。
判定器不能被判定对象改写。

**为什么不用「再写一条守卫」**：守卫只能看到工具调用，看不到「人有没有点过确认」。
若把审批标记放进工作区，agent 顺手写一个就绕过了 —— 那只是把伪造点从一个文件挪到另一个文件。

**实际做法**（`lib/patch-approval.js`）：

```
审批文件：~/.dsh/cto-office-patch-approval.json   ← 工作区之外
CTO 会话沙箱：workspace-write                     ← agent 写不到那里
能写它的：人（或人在终端跑的 scripts/approve-patch-edit.mjs）
```

这不是「又一条运行时判断」，而是**能力层剥夺** —— 与「工具按岗位挂载、不靠运行时收窄」是同一原则。

- 拦截范围：`write` / `edit` 目标为 `cordis.patch.yml`；`bash` / `pwsh` 命令提及该文件且不是只读命令。
- 只读命令放行：`cat` / `grep` / `git diff` / `npm run check` 等（否则连读都不许，没法排障）。
- 审批 **30 分钟过期**，一次一问（§14.10 的「例外门」，不是第二个日常入口）。
- 读不到 / 坏 JSON / schema 不对 / 过期 → 一律按**未批准**处理（fail-closed）。

给人用的脚本：

```bash
node scripts/approve-patch-edit.mjs --reason "给 cto-ux 加 read_image 走查能力"
```

## 第三处：锁 TTL

`exclusiveClaimState(card, now, ttlMs)` 是纯函数（`lib/card.js`）：

- **活动即续租**：`store.save()` 推进 `updatedAt`，所以 gate / 回执 / note 都算活动，不需要单独续租动作。
- 默认 TTL **45 分钟**，`exclusiveTtlMs` 可配（阈值是参数不是常量）。
- **过期只解除阻塞，不改 `authorization`**：授权是 judge 判越界的对照物，取消授权等于让越界判定失效。
- 过期先例：到期后别的卡派工不再被它挡；该卡自己的判定仍按原授权走。

### 一个必须踩到的坑：审计不能把锁续上

第一版写「审计 = `store.appendHistory` + `store.save`」。但 `save()` 会把 `updatedAt` 设成 `now` ——
于是**记一笔审计顺手就把锁续上了**，TTL 永远不生效。所以新增 `store.appendHistory()`：
追加 history 但**冻结 `updatedAt`**。测试里专门断言了「审计后 `updatedAt` 不变、claim 仍然过期」。

### 第二个坑：两处入口逻辑漂移

互斥检查原先有**两份**：新建卡分支一份、`startIfPossible`（启动排队卡）另一份。
第一版只给前者加了 TTL，结果出现「审计说已忽略，卡却仍然排队」——测试当场抓住。
现在两处共用 `exclusiveConflictFor()` 一个助手，并加注释说明为什么不能各写一套。

## 监督器报警

锁 TTL 到期会进监督器：`reason: exclusive-expired`、`action: suggest-abandon`，
消息里带可执行选项（`office_release <id> action=abandon` 或让它继续产出）。
同一张卡同一原因只报一次，避免每 15 分钟刷一条同样的噪音。
